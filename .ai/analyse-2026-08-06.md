## Résumé

Le projet NerdMC est un bot Discord de pont entre le tchat Minecraft et Discord. L’architecture est simple, mais la version actuelle présente des risques de robustesse et de sécurité : gestion fragile du sous-processus `tail`, configuration non validée, utilisation de `sudo` et absence évidente de `.gitignore` pour protéger le token Discord.

## Problèmes et bugs potentiels

- `main.py` : lecture de `config.json` sans `try/except`. Si le fichier est absent ou invalide, le bot crashe sans message explicite.
- `main.py` : `config['command_prefix']` peut lever `KeyError` si la clé est absente. Utiliser `config.get()` et vérifier les clés obligatoires.
- `main.py` : `use_sudo = config.get('use_sudo', True)` ne vérifie pas le type. Si la valeur est la chaîne `"false"`, elle est considérée comme vraie.
- `main.py` : `subprocess.Popen` pour `tail -f` est utilisé dans un contexte asynchrone. Une lecture synchrone des sorties peut bloquer la boucle événementielle de Discord. Préférer `asyncio.create_subprocess_exec`.
- `main.py` : aucune protection contre un double `enable`. Deux processus `tail -f` peuvent être lancés et provoquer des messages en double.
- `main.py` : `ctx.author.guild_permissions` suppose que la commande est exécutée sur un serveur. En message privé, cela peut lever une exception. Vérifier `ctx.guild` avant.
- `main.py` : l’activité Discord est codée en dur avec `mc.forezaaaa.fr`. La déplacer dans la configuration.
- `nerdmc_console.sh` : `tmux new-session` échoue si la session `minecraft` existe déjà. Le script devrait vérifier l’existence de la session avant de démarrer.
- L’état global `stop_reading` est fragile ; s’il est partagé entre plusieurs commandes, il peut créer des incohérences. Préférer un attribut sur l’objet `bot`.

## Qualité du code et nettoyage

- Extraire la lecture de configuration dans une fonction `load_config()` avec validation des clés, types et valeurs obligatoires.
- Remplacer les `print()` par le module `logging`.
- Ajouter un `.gitignore` couvrant au minimum `config.json`, les fichiers `*.log`, `__pycache__/` et `.env`.
- Nettoyer `requirements.txt` : plusieurs paquets listés sont probablement des dépendances transitives. Ne conserver que les dépendances directes, ou utiliser `pip-tools`.
- Si `ruff.toml` est présent, s’assurer que `.github/workflows/ci.yml` exécute bien `ruff check .` ; sinon l’ajouter.
- Documenter la variable d’environnement `NERDMC_CONFIG` et le schéma attendu de `config.json`.

## Nouvelles fonctionnalités à envisager

- Ajouter ou vérifier une commande `disable` qui arrête proprement la lecture du log et tue le processus `tail`.
- Ajouter une commande `status` pour indiquer le canal actif, l’état du processus `tail` et la session tmux concernée.
- Permettre l’envoi de commandes console Minecraft depuis Discord (ex. whitelist) via `tmux send-keys`, réservé aux administrateurs.
- Si le log Minecraft contient les événements de connexion/déconnexion, les envoyer sur Discord en plus des messages du chat.

## Tests manquants

- Tests unitaires pour la validation de la configuration : fichier manquant, clés absentes, `use_sudo` non booléen.
- Tests unitaires pour le formatage des messages Minecraft avant envoi sur Discord.
- Test d’intégration minimal pour le lancement et l’arrêt de `tail -f` sur un fichier temporaire.
- Ajout de `shellcheck` sur `nerdmc_console.sh` dans la CI.

## Dépendances et sécurité

- Le bot exécute `sudo tail` et potentiellement `sudo tmux`. Restreindre sudo dans `sudoers` aux commandes précises nécessaires, sans donner un accès root global.
- Le token Discord est stocké dans `config.json` ; un `.gitignore` est indispensable pour éviter de le committer.
- Renovate est déjà actif (issue #3) : continuer à appliquer les PR de mise à jour.
- Ajouter un outil d’audit de dépendances comme `pip-audit` ou `osv-scanner` dans la CI.
- Utiliser un `requirements.txt` réduit aux dépendances directes pour limiter la surface d’attaque et faciliter les mises à jour.

## Suggestions prioritaires (top 5)

1. Ajouter un `.gitignore` et vérifier l’historique Git pour s’assurer qu’aucun secret n’a été commité.
2. Remplacer `subprocess.Popen` par `asyncio.create_subprocess_exec` avec gestion de l’arrêt propre du processus `tail` et protection contre les doubles lancements.
3. Durcir la lecture de `config.json` : validation des clés obligatoires, types corrects et message d’erreur explicite.
4. Restreindre les droits sudo dans `sudoers` aux seules commandes utilisées par le bot.
5. Mettre en place des tests unitaires et un pipeline CI exécutant `ruff`, `shellcheck`, `pytest` et `pip-audit`.
